## 一、目标与范围理解

### 1) 核心目标与输出路径变化
- 你的答案：
  - 不适用sbi来打印字符，而是使用uart组件打印字符。
- 标准答案：
  - 目标是把 ch1 内核的字符输出路径从 `tg_sbi::console_putchar` 改为 S-Mode 下 UART16550 MMIO 轮询发送。
  - 关机路径仍由 SBI 提供 `shutdown`。
  - 本质变化：输出从“固件提供的字符服务”改为“内核直接驱动串口硬件”。
- 评价：基本正确。
- 错误原因：无实质错误。
- 遗漏原因：
  - 未明确“轮询发送（LSR.THRE）”与“关机仍走 SBI”这两个关键点。

### 2) 为什么输出走 UART、关机保留 SBI
- 你的答案：
  - uart是设备的输入输出，sbi提供的是操作系统的运行时环境。
- 标准答案：
  - UART 驱动负责设备 I/O（此处是字符发送），属于内核设备访问能力。
  - SBI 是 S-Mode 向 M-Mode 请求最小固件服务的接口，关机在本实验中仍依赖 SBI 更简洁可靠。
  - 职责边界：I/O 数据路径下沉到内核驱动；平台控制服务仍由 SBI 承担。
- 评价：方向正确。
- 错误原因：表述“运行时环境”不够准确，SBI更准确是“固件调用接口规范”。
- 遗漏原因：
  - 未说明“教学上分离输出路径与关机路径”的设计目的。

### 3) 最小可运行目标与一次验证

- 标准答案：

  - 一次验证：运行 `cargo run` 或 `bash test.sh`，输出匹配且进程正常结束。
- 评价：不正确。
- 错误原因：

- 遗漏原因：

### 4) 两个 crate 的分工

## 三、串口驱动实现原理

### 9) 关键寄存器与作用
- 你的答案：
  - LSR线路状态寄存器，用于状态检测
  - THR发送保持寄存器，写入待发送的字节
- 标准答案：
  - 当前发送路径核心寄存器：
    - `THR`（`base + 0x00`）：发送保持寄存器，写入待发送字节
    - `LSR`（`base + 0x05`）：线路状态寄存器，读取发送状态
    - `LSR.THRE`（bit5）：发送保持寄存器空标志
- 评价：正确。
- 错误原因：无。
- 遗漏原因：
  - 未写出偏移地址与 THRE 位号。

### 10) 为什么检查 THRE
- 你的答案：
  - LSR的THRE位是发送缓冲区是否为空的标志，如果不检查直接写会出现发送缓冲区已满，原数据会被写入的数据覆盖，丢失原来的数据。
- 标准答案：
  - 需在发送前等待 `THRE=1`，保证发送保持寄存器可接受新字节。
  - 不检查会导致写入时机错误，可能出现数据丢失或行为不可预期。
- 评价：正确。
- 错误原因：无。
- 遗漏原因：可补充“忙等会增加 CPU 占用”。

### 11) volatile 访问必要性
- 你的答案：
  - 为了让读写寄存器的操作为原子操作，同时避免直接读写硬件的操作不被rust编译器优化。
- 标准答案：
  - `read_volatile/write_volatile` 的核心作用是阻止编译器消除/重排关键 MMIO 访问。
  - 它不等价于“原子操作”，原子性需另行保证（锁/指令语义）。
- 评价：部分正确。
- 错误原因：
  - 把 volatile 与原子性混淆。
- 遗漏原因：
  - 未指出“MMIO 对副作用敏感，必须保序地真实访问”。

### 12) 为什么基址常用 `0x1000_0000`
- 你的答案：
  - 未作答
- 标准答案：
  - QEMU `virt` 平台把 UART16550 映射在固定 MMIO 地址区，常见基址为 `0x1000_0000`。
  - 该地址是驱动与虚拟硬件“对齐”的关键前提，写错会导致无输出或访问异常。
- 评价：未作答。
- 错误原因：无。
- 遗漏原因：
  - 对平台内存映射表（设备树/virt 约定）不熟悉。

### 13) 为什么内部 unsafe、外部安全接口
- 你的答案：
  - unsafe意味着rust编译器不保证安全，需要写代码的人保证安全。
- 标准答案：
  - 访问裸指针 MMIO 属于不安全操作，需在驱动内部封装 `unsafe`。
  - 对外提供受限、安全 API（如 `uart_puts`），由模块内部维护不变量与地址正确性。
- 评价：正确。
- 错误原因：无。
- 遗漏原因：
  - 未明确“封装 unsafe 边界”的工程意义。

### 14) 为什么把 `\n` 转为 `\r\n`
- 你的答案：
  - 为了在终端上显示换行，需要将\n转换为\r\n。若不转换，终端会将\n解释为一个字符，而不是换行。
- 标准答案：
  - 许多串口终端采用 CRLF 语义，`\n` 仅换行不回到行首，`\r\n` 才更兼容。
  - 不转换时常见现象是行首错位或显示效果异常。
- 评价：基本正确。
- 错误原因：
  - “`\n` 被解释为普通字符”表述不准确；通常仍是换行但可能不回车。
- 遗漏原因：可补充“兼容不同终端行为”的背景。

## 四、轮询方式实现原理

### 15) 轮询发送步骤
- 你的答案：
  - 先读取LSR寄存器，判断THRE位是否为1，即发送缓冲区是否为空。
  - 如果THRE位为1，说明发送缓冲区为空，可以写入数据。
  - 如果THRE位为0，说明发送缓冲区已满，需要等待。
  - 写入数据到THR寄存器，数据会被发送到串口。
- 标准答案：
  - 循环读取 LSR → 判断 THRE → 就绪后写 THR → 返回/处理下一字节。
- 评价：正确。
- 错误原因：无。
- 遗漏原因：可补充“这是 busy-wait”。

### 16) 轮询优缺点
- 你的答案：
  - 优点：实现简单，不需要中断
  - 缺点：会一直占用CPU，CPU效率低下
- 标准答案：
  - 优点：实现简单、调试直观、依赖少。
  - 缺点：CPU 空转、吞吐受限、并发扩展性差。
- 评价：正确但不完整。
- 错误原因：无。
- 遗漏原因：
  - 题目要求“至少两个优点和两个缺点”，你各只给了一个。

### 17) 轮询 vs 中断差异
- 你的答案：
  - 未作答
- 标准答案：
  - 实现复杂度：轮询低，中断高（需中断控制与上下文处理）。
  - CPU 占用：轮询高，中断低。
  - 实时性：中断通常更优，但实现复杂、时序调试更难。
- 评价：未作答。
- 错误原因：无。
- 遗漏原因：可能对“中断路径全链路”尚不熟。

### 18) 为什么 ch1 选轮询
- 你的答案：
  - ch1是简单内核，没有时钟中断，同时要从小的地方入手，先写出来，再想着优化。
- 标准答案：
  - ch1 目标是最小可运行闭环，轮询足够达成目标且成本最低。
  - 中断会引入额外机制，超出本阶段教学重点。
- 评价：正确。
- 错误原因：无。
- 遗漏原因：可补充“减少变量，便于定位错误”。

### 19) 发送阻塞过长如何排查

## 六、启动与运行链路

### 24) `-bios none` 下 M/S 模式责任
- 你的答案：
  - M-Mode与硬件有关，应该是初始化各种寄存器，中断向量表之类的功能然后跳转到S-Mode
  - S-Mode与内核有关，应该初始化内核栈、全局变量，调转到rust_main
- 标准答案：
  - M-Mode（由 tg-sbi 提供）：最小硬件/平台初始化并跳转到 S-Mode 入口。
  - S-Mode（本内核）：设置栈并执行内核主流程。
- 评价：正确。
- 错误原因：无。
- 遗漏原因：可补充“入口地址由链接脚本约束”。

### 25) `M_BASE_ADDRESS` / `S_BASE_ADDRESS`
- 你的答案：
  - M_BASE_ADDRESS对应M-Mode的代码区域，S_BASE_ADDRESS对应S-Mode的代码区域。
- 标准答案：
  - `M_BASE_ADDRESS=0x80000000`：M-Mode 区域。
  - `S_BASE_ADDRESS=0x80200000`：S-Mode 区域（含 `_start`）。
- 评价：正确。
- 错误原因：无。
- 遗漏原因：可补充具体地址数值。

### 26) 为什么先设栈再进 Rust
- 你的答案：

- 标准答案：
  - Rust 函数调用、局部变量、调用约定都依赖有效栈指针；无栈进入会立即不可靠。
- 评价：正确。
- 错误原因：无。
- 遗漏原因：可补充“_start 是裸函数，必须手工建栈”。

### 27) `build.rs` 作用与缺失后果
